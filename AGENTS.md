# AGENTS.md — klarkc/os

## Active operator decisions (2026-11-11)

- **main-only Git workflow.** `main` is the sole branch for new development, tests, documentation and integration. Do not create/push feature, host, migration or release branches; do not open new PRs or start new Git worktrees. Verify current `main` HEAD and file blob SHAs, reconcile concurrent work, commit non-destructively and never force-update or rewrite history. Historical feature branches are *read-only recovery sources* until their differences are reviewed and integrated on `main`; do not delete them without explicit approval. Do not blindly merge diverged Dell and GCE branches.
- **Only NixOS, no Arch compatibility.** Retire Arch/AUR/pacman/yay, fixed `/usr/bin` or `/opt` assumptions and legacy NVIDIA/nixGL GPU profiles. NixOS is the only supported Linux OS; the Windows client is a supported access fallback, **not** a declarative NixOS host. Host-specific GPU drivers are allowed **only** on compatible future ARM hardware after validation and explicit acceptance. Prefer pinned flakes and declarative NixOS + Nix-managed user modules; never substitute manual `nix profile install` or live package-manager commands for committed configuration.
- **One source of truth: `klarkc/os`.** This public repository owns **both host-level NixOS and all `klarkc` user configuration**: XMonad, shell, Brave, Enpass, themes, shortcuts, fonts, user units, developer tools, GCE/XRDP/IAP, security, boot/ISO, storage and networking. `klarkc/dotfiles` is archived, read-only **historical migration evidence**; do not push to, import unreviewed commits from, install profiles from, or keep runtime dependencies on it. Prefer a shared Nix module extended by thin-client/GCE/ARM host modules instead of copying application or profile definitions. The existing GCE Brave/Enpass system closure is the temporary P0 baseline; consolidate ownership as tested common user modules without duplicate installations.
- **Desktop production acceptance.** Operator has already confirmed real authenticated Windows RDP through IAP to the existing GCE NixOS XMonad desktop. Brave + Enpass (and their real browser/vault integration) are P0 SoloSIG requirements. Bidirectional XRDP speaker/microphone is a later, independent gate and must not block the initial development setup. Legacy physical-monitor XMonad commands and Arch `/usr/bin`/`/opt` paths must not override virtual XRDP sessions.
- **Preserve live infrastructure and user data.** Never make a Git commit or green QEMU CI imply the running GCE VM is updated. Production NixOS activation, image rebuild/import, disk replacement, reboot, paid Cloud changes, IAM/VPC/NAT, disabling RDP/SSH or handling private user HOME require separate safe rollout evidence and operator authorization where applicable. Protect the existing 256-GiB persistent boot disk, current XRDP credentials, user HOME and files. Guard dotfiles checkout against collisions; no `git clean`, blanket `make`, unattended user-service activation or invasive HOME changes. Validate fallback/rollback before any change that could interrupt access.
- **Security/privacy.** This repository is public. Never publish passwords, OAuth tokens, vault data, browser profiles, runtime secrets, keys, internal or customer private data. Enpass login, cloud IAM and provider credentials are interactive/runtime-only, outside Nix derivations, Git, metadata and CI. Inspect file diffs and source hashes, execute available Nix evaluation/QEMU/source and safety tests before promoting, and report unverified tests explicitly. Never bypass access/security denial by switching tools or endpoints.
- **Branch-bound automation migration.** Existing workflows and Google workload identity policies may still refer to retired feature branch names. Treat those production deploy paths as **not authorized for main** until separately reviewed, safely migrated to exact main-bound identity rules, and independently tested. Keep paid production jobs opt-in; never edit IAM or trigger paid builds/deployments merely to implement the main-only source policy.
- **GitHub operations.** Before a write, check readback and current `main` HEAD. For multi-file changes, prepare one tree/commit on the current ancestor and advance `main` with expected-HEAD, non-force compare-and-swap. On ambiguous writes reconcile provider commit/path/HEAD before any retry. Do not claim release complete without passing tests and (when needed) operator-verified live application.

## Carried-forward safeguards from archived dotfiles

These rules replace and adapt the useful parts of archived `klarkc/dotfiles/AGENTS.md`. In case of conflict, the active `klarkc/os` ownership, `main`-only policy and the above phases take precedence; old `$HOME`-is-a-repository, worktree, Arch and `nix profile upgrade klarkc` instructions do **not** apply.

- **Privacy and Git discipline (public repository):** treat tracked content, tests, documentation, commit messages and history as publicly visible. Do not add real customer/organization names, personal identifiers, deployment endpoints, IP addresses, host identities or local user paths in new public examples without explicit publication approval. Prefer synthetic documentation examples and runtime-supplied, ignored configuration. Recheck the exact proposed staged/tree diff for secrets and private metadata before every commit; run existing Gitleaks/pre-commit privacy checks where available; keep scanner reports private and redacted. A negative scan never proves absence of leaks. If suspected exposure is found, stop and report file/line/classification without printing any secret; recommend rotation and obtain approval before any history rewrite. Never bypass hooks with `--no-verify`, `SKIP` or alternate Git paths.
- **Secrets are runtime-only:** no credentials, SSH keys, Enpass vault/profile, browser cookies, OAuth tokens or personal session backups in Git, Nix store, images, cloud metadata, CI output or process arguments. Where the legacy Linux workflow needs `~/.profile_override`, keep this file ignored, readable only by its owner and **values-only** (assignments/exports/comments, no executable logic); derive runtime values in versioned scripts after sourcing it. Other provider-managed private stores or OS keychains may be used only with explicitly reviewed security. Temporary credential material belongs under user-private `$XDG_RUNTIME_DIR` (0700 directory / 0600 files) with bounded lifetime, not to public source. The Windows thin-client may persist nonsecret resource identifiers under the user's private app-data path, but never credentials.
- **Nix reproducibility and no duplicated ownership:** all dependencies fetched by **repo-maintained Nix code** must be declared via appropriate canonical flake inputs and locked revisions/hashes, not live `fetchTarball`, mutable `<nixpkgs>`, `curl`, `git clone`, `npm install` or `pip install` in a Nix build. Prefer Nix-native builders; if an ecosystem resolver must be used, operate offline on already-locked inputs. Upstream derivations are not subject to our repo-maintained-code restriction unless patched or vendored. Do not duplicate the same program's Nix package/profile/service definition across modules; **extend/import** the single owner and use host-specific option overrides only where justified.
- **Coupled updates:** when a source, version, hash or runtime is pinned, add a nearby actionable bump note describing the companion inputs/hashes/wrappers/tests to update. Update coupled parts together. Follow existing Nixpkgs branch input URLs and rely on `flake.lock` for determinism; do not turn normal upstream branch inputs into arbitrary fixed URLs just to pin them.
- **Service and package activation:** never build/download packages at unit startup, enable all migrated user services automatically, or run blanket `make`, destructive cleanup, `git clean -fdx`, Nix garbage collection or deletion of recovery data to force a migration. Use immutable Nix store paths or defined profile references in systemd units and explicit activation/rollback. Do not alter a running XMonad/XRDP/SSH session, disk, secrets or Enpass integration without a safe test and recovery path.
- **Testing contract:** on every substantive change, use the repository's actual applicable Nix evaluation/check and offline QEMU/CI gates, plus the relevant source/static tests; run native Git hooks and privacy checks when a connected development runtime supports them. The archived dotfiles `make test` and `nix develop` are *not* automatically valid gates for this repository. Never skip an applicable gate just to pass a commit; if a GitHub connector writes source without being able to run local hooks, report the limitation and do not call it locally tested. For live GCE/Dell/ARM changes, require separately reported operator/device E2E after the offline gates.
- **Historical recovery:** do not merge archived dotfiles history or deprecated secret-bearing commits into this public repository. Extract reviewed, necessary **source content only**, with privacy checks, and no private OptMem data/worktrees or Enpass vault. Private recovery repositories and devices are independent: never copy their data to `klarkc/os` or mutate them as part of a code migration.
