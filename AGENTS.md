# AGENTS.md — klarkc/os

## Active operator decisions (2026-11-11)

- **main-only Git workflow.** `main` is the sole branch for new development, tests, documentation and integration. Do not create/push feature, host, migration or release branches; do not open new PRs or start new Git worktrees. Verify current `main` HEAD and file blob SHAs, reconcile concurrent work, commit non-destructively and never force-update or rewrite history. Historical feature branches are *read-only recovery sources* until their differences are reviewed and integrated on `main`; do not delete them without explicit approval. Do not blindly merge diverged Dell and GCE branches.
- **Only NixOS, no Arch compatibility.** Retire the Arch/AUR/pacman/yay/NVIDIA/nixGL legacy runtime. Do not retain Arch-specific shell, GTK, XMonad, driver, package or systemd assumptions as supported behavior. Prefer pinned flakes, declarative NixOS modules and tested Nix user modules; never substitute manual `nix profile install` or live package-manager commands for committed configuration.
- **Configuration ownership is explicit.** `klarkc/os` owns OS/host-level infrastructure: kernel, boot/ISO, GCE image/VM integration, SSH/OS Login, IAP, firewall/network, system services, XRDP/Xorg backend, storage, audio transport and operational safety. `klarkc/dotfiles` is the preferred authoritative source for the user `klarkc`'s XMonad configuration, shell, graphical applications (including Brave/Enpass), themes, shortcuts, fonts, user systemd units and developer tooling. Migrate conflicting user config into declarative Nix there; do not duplicate/override it in both repositories. The existing GCE system-level Brave/Enpass closure is a **temporary P0 bootstrap baseline** to be consolidated with `dotfiles` once the user-level Nix integration is validated.
- **Desktop production acceptance.** Operator has already confirmed real authenticated Windows RDP through IAP to the existing GCE NixOS XMonad desktop. Brave + Enpass (and their real browser/vault integration) are P0 SoloSIG requirements. Bidirectional XRDP speaker/microphone is a later, independent gate and must not block the initial development setup. Legacy physical-monitor XMonad commands and Arch `/usr/bin`/`/opt` paths must not override virtual XRDP sessions.
- **Preserve live infrastructure and user data.** Never make a Git commit or green QEMU CI imply the running GCE VM is updated. Production NixOS activation, image rebuild/import, disk replacement, reboot, paid Cloud changes, IAM/VPC/NAT, disabling RDP/SSH or handling private user HOME require separate safe rollout evidence and operator authorization where applicable. Protect the existing 256-GiB persistent boot disk, current XRDP credentials, user HOME and files. Guard dotfiles checkout against collisions; no `git clean`, blanket `make`, unattended user-service activation or invasive HOME changes. Validate fallback/rollback before any change that could interrupt access.
- **Security/privacy.** This repository is public. Never publish passwords, OAuth tokens, vault data, browser profiles, runtime secrets, keys, internal or customer private data. Enpass login, cloud IAM and provider credentials are interactive/runtime-only, outside Nix derivations, Git, metadata and CI. Inspect file diffs and source hashes, execute available Nix evaluation/QEMU/source and safety tests before promoting, and report unverified tests explicitly. Never bypass access/security denial by switching tools or endpoints.
- **Branch-bound automation migration.** Existing workflows and Google workload identity policies may still refer to retired feature branch names. Treat those production deploy paths as **not authorized for main** until separately reviewed, safely migrated to exact main-bound identity rules, and independently tested. Keep paid production jobs opt-in; never edit IAM or trigger paid builds/deployments merely to implement the main-only source policy.
- **GitHub operations.** Before a write, check readback and current `main` HEAD. For multi-file changes, prepare one tree/commit on the current ancestor and advance `main` with expected-HEAD, non-force compare-and-swap. On ambiguous writes reconcile provider commit/path/HEAD before any retry. Do not claim release complete without passing tests and (when needed) operator-verified live application.
